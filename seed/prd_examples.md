# PRD 示例库

用于 Milvus 语义检索，为「业务拆解 Agent」提供同类产品 PRD 参考。每个 `## ` 标题块作为一条独立向量。

## 内部报销系统 PRD

业务背景：员工日常垫资报销依赖纸质单据与线下审批，流程慢且易丢失。目标是把报销从提交、审批到打款全流程线上化，平均审批时长从 3 天降到 1 天。
用户角色：普通员工（发起报销、查看进度）、部门负责人（审批）、财务审核员（复核与打款）、管理员（配置报销类型与金额上限）。
功能需求：
- 发起报销：员工填写类型、金额、事由并上传票据附件，系统校验金额上限后生成报销单。
- 异常流程：票据不清晰提示重传；金额超限拦截并提示走特批流程；网络异常自动暂存草稿。
- 验收标准：提交成功生成单号且状态为「待审批」；超限金额无法提交并给出明确提示。
非功能需求：报销单查询响应 < 2 秒；金额与附件加密存储；权限分级（员工仅可见本人单据）。

## 电商订单管理系统 PRD

业务背景：多平台订单分散在各自后台，运营需人工汇总，易漏单错单。目标：统一聚合多平台订单，自动同步状态。
用户角色：运营（查看订单）、客服（处理售后）、仓库（发货）、管理员（平台接入配置）。
功能需求：
- 订单同步：定时拉取各平台订单，去重合并为统一订单。
- 异常流程：平台接口限流时进入重试队列；订单状态冲突时标记待人工确认；同步失败邮件告警。
- 验收标准：5 分钟内完成一次全量同步；重复订单不产生重复记录；同步失败有告警且有重试机制。
非功能需求：单平台单次同步 ≤ 1 万单；订单金额脱敏展示；支持新增平台插件式接入。

## 员工考勤系统 PRD

业务背景：考勤数据分散、排班靠人工，统计易出错。目标：实现打卡、排班、异常申诉与月度统计一体化。
用户角色：员工（打卡、查看与申诉）、主管（审批申诉、查看团队）、HR（排班与统计）。
功能需求：
- 月度统计：自动汇总出勤、迟到、早退、请假，生成报表。
- 异常流程：打卡设备故障时支持手机补卡并留痕；申诉超时自动关闭；统计口径变更需版本记录。
- 验收标准：月度报表生成准确率 100%（以 HR 抽查为准）；申诉在 1 个工作日内有审批结果。
非功能需求：月报生成 ≤ 30 秒；考勤数据只读加密；按角色控制报表可见范围。

## 客户关系管理 CRM PRD

业务背景：客户资料散落在 Excel，跟进无记录，销售撞单频发。目标：统一客户池、跟进留痕、公海回收。
用户角色：销售（录入与跟进）、销售主管（分配与查看）、管理员（权限与字段配置）。
功能需求：
- 客户公海：超过 N 天未跟进的客户自动回收进公海，可被重新领取。
- 异常流程：并发领取同一客户时以先到者为准；回收触发短信提醒原负责人；字段修改留审计日志。
- 验收标准：撞单时仅一位销售获得客户归属；回收与领取均有通知与记录。
非功能需求：列表页查询 < 1 秒；客户手机号加密存储；导出数据需管理员审批。
